# MTProto、TUIC 与隧道协议策略现状

本页记录当前本地实现和后续缺口。倍率只改变流量额度扣减，不涉及金钱。各层最高速度与配额能否实际执行取决于协议，详见下表；经过 Xray 出站不等于侧车中的真实客户端身份已传给 Xray。

| 协议 | 当前已实现 | 尚未支持或限制 |
| --- | --- | --- |
| MTProto | `mtg-multi` 以每个 secret 识别客户端并上报物理流量；入站配置最高上行或下行时，侧车经带独立凭据的本地 Xray SOCKS 桥接，执行**整个入站聚合**最高速度；面板按 secret 计算入站倍率扣减（含 0.01× 小数累计），同步调整 mtg 原生总额；客户端和单关联入站的固定/滚动窗口按扣量后的流量计费，耗尽后移除 secret，窗口恢复后重新启用。旧入站的桥接端口与凭据在启动时补齐。 | 侧车桥接只看得到一个合成用户，不能执行每 secret 的最高上行/下行速度、窗口耗尽后的慢速、超额二次限速或到期后的低速宽限；mtg 原生到期时间会在宽限开始时直接停用 secret。旧配置或 API 如果给 MTProto 窗口设了 `throttle`，耗尽时按**停止**执行，防止无意放行。统计轮询与 secret 热更新之间可能有短暂超额。 |
| TUIC | 公网 UDP 中继对加密数据包实施整个入站聚合的最高上行/下行速度，支持运行中改速；被拒绝的数据包不占用客户端流表。 | 中继无法从加密报文可靠识别认证后的用户，因此不能执行客户端或关联入站级速度、额度、窗口、倍率和到期低速宽限。非 1× 入站倍率在后端被拒绝。聚合最高速度按加密 UDP 字节计，实际载荷速度会略低。 |
| WireGuard | 补丁 Xray 核心依据 peer 的隧道源地址识别真实客户端邮箱，通过 Xray 调度器执行入站、客户端和关联入站的双向最高速度、额度/窗口及到期低速宽限规则；重叠 AllowedIPs 按最长前缀归属，等长冲突拒绝归属。 | 与其他 Xray 协议一样，策略文件更新至运行中核心存在短暂刷新间隔。 |
| AmneziaWG | 独立内嵌转发器提供 peer 流量统计，并通过 Xray 出站。 | 尚未把原 peer 身份可靠传给 Xray 策略层；客户端级速度、窗口耗尽后慢速和到期低速宽限仍需在 peer 转发边界实现。 |

## 后续实施点

1. 在 `mtg-multi` 已认证的每 secret 收发路径增加双向令牌桶及窗口、超额和宽限策略热更新，保留现有 secret、广告标识和物理流量统计。
2. 在 TUIC 服务端解密且认证后的用户收发路径增加按 UUID 的统计、策略和热更新接口；面板 UDP 中继仅继续负责入站聚合速度，不把加密 UDP 数据包归给某个客户端。
3. 在 AmneziaWG 的 peer 与 gVisor 转发边界实施策略，按 peer 公钥和客户端 ID 归属流量，覆盖 TCP、UDP 和端口转发，避免与 Xray 出站重复计数。
4. 所有实现保持物理上传/下载计数与额度扣减分离；重置、进程重启和多节点同步使用同一账户口径。部署前备份数据库与运行文件，并在隔离环境验证旧数据升级和回滚。

## 验证门槛

- 分协议核对最高上行/下行、0 值、窗口边界、0.01× 小数累计、并发客户端、重连、进程重启及旧数据升级。
- 对每种策略同时检查实际传输、物理流量、额度扣减和分享页剩余值；未实现的组合不得显示为已生效。
- Linux 产物应在隔离环境完成端到端测试与升级恢复演练；生产测试和部署另行授权。
